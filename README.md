# مخططات قاعدة بيانات السوبر ماركت

مخططات ER لنظام محاسبي ومخزني للسوبر ماركت. هذه وثائق تصميم أولية لقاعدة بيانات SQLite، مع مراعاة إمكانية الانتقال لاحقًا إلى SQL Server.

## تنفيذ SQLite

أضيف تنفيذ قابل للتشغيل مع 68 جدولًا و35 اختبارًا وبيانات افتراضية. راجع [تعليمات التشغيل في Codespaces والجوال](database/README.md)، و[تقرير مراجعة التصميم والقرارات](docs/design-review.md)، و[خطة الانتقال إلى SQL Server](docs/sql-server-migration.md). تبقى المخططات أدناه مرجع التصميم الأصلي.

```bash
python -m unittest discover -s tests -v
python -m database.engine supermarket.sqlite --seed
python -m database.demo supermarket-demo.sqlite
```

## قواعد أساسية
- دعم معالجة شحن المشتريات إما بتحميله على المخزون وتوزيعه على الأصناف أو كمصروف مستقل إذا كان ذلك مناسبًا محاسبيًا.
- عند التوزيع يجب أن يساوي مجموع التخصيصات مبلغ الشحن.
- رصيد المخزون بمفتاح مركب (المستودع، المنتج)، ورصيد الدفعات بمفتاح (المستودع، الدفعة).
- الحفاظ على توازن القيود المحاسبية وعدم تكرار الأثر المالي.
- حركة المخزون الفعلية عند الاستلام/الصرف وليس مجرد إصدار المستند.

## ملاحظات قبل توليد SQL
هذه مخططات تصورية وليست سكربتات إنشاء جاهزة. ينبغي تدقيق المراجع متعددة الأشكال في حركات المخزون والقيود، وآلية تكلفة الدفعات، وتخصيص الشحن على الكميات المستلمة، ومنع تجاوز كميات المرتجعات والاستلامات، وتزامن الأرصدة. يجب اختبارها قبل اعتبار النظام جاهزًا للإنتاج.

## تدقيق التصميم
- [ضوابط التنفيذ والقيود المحاسبية والمخزنية](docs/implementation-rules.md) — اقرأها قبل أن يكتب Codex ملفات SQLite.
- تم توثيق مصادر الحركات متعددة الأنواع كمراجع منطقية، وليست مفاتيح FK فعلية حتى يكتمل تطبيق قيودها.
