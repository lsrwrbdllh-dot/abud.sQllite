# صلاحيات الموظفين — الإصدار 1.1.0

اعتمد المالك الأدوار والصلاحيات في المحادثة ثم طلب «نفذ» بتاريخ 2026-10-26.
هذا نظام حسابات محلية على الهاتف نفسه؛ لا يضيف خادماً أو مزامنة بين الأجهزة.

## أول تشغيل

عند إنشاء متجر تدخل اسم مستخدم المدير وكلمة مروره (8–256 حرفاً). لا توجد كلمة مرور افتراضية.
عند فتح قاعدة الإصدار السابق تظهر «إعداد حساب المدير» مرة واحدة؛ تبقى المنتجات والأرصدة والحركات كما هي.
صاحب الجهاز الذي ينفذ هذا الإعداد يصبح المدير الأول، لذلك ينفذه مالك المتجر قبل تسليم الجهاز للموظفين.
بعد إغلاق عملية التطبيق يلزم تسجيل الدخول. الجلسة تنتهي بعد 15 دقيقة دون أوامر أو بعد 8 ساعات كحد أقصى.

## إدارة الموظفين

1. ادخل بحساب المدير، وافتح «إدارة الموظفين والصلاحيات» ثم «إضافة موظف».
2. أدخل اسم الموظف واسم دخوله وكلمة مروره واختر الدور.
3. حدد الصناديق والبنوك المسموحة. الموظف الذي لا يملك «استخدام جميع الصناديق» لا يستطيع استخدام صندوق خارج هذه القائمة.
4. افتح «تخصيص صلاحيات الموظف»: لكل جدول عرض، إضافة، تعديل، حذف، اعتماد، طباعة وتصدير، حيث تنطبق العملية.
5. احفظ. تعديل كلمة المرور أو الدور أو الصلاحيات أو حالة الحساب ينهي جميع جلسات الحساب فوراً.

الحساب يوقف ولا يحذف، حتى تبقى هوية منفذ الحركات القديمة محفوظة. لا يمكن إيقاف أو تخفيض دور آخر مدير نشط.
المدير يملك جميع الصلاحيات؛ إلغاء مربعات الصلاحيات لا يقيد دور المدير. استخدم دوراً آخر لتقييد الحساب.
لكل حساب دور جاهز واحد، مع استثناءات سماح/منع خاصة به. لا تغير تخصيصات الموظف الدور الافتراضي لبقية الموظفين.

## الأدوار الافتراضية

| الدور | السلوك الافتراضي |
| --- | --- |
| المدير | كل الصلاحيات، مع بقاء حماية المستندات المعتمدة والآثار والسجلات. |
| الكاشير | مبيعاته وأسطرها، قبض العملاء وتوزيعه، العملاء والأصناف والكميات، وصناديقه المحددة. يعد مرتجعاً كمسودة؛ اعتماد المرتجع يحتاج إذناً إضافياً. لا يرى التكلفة أو الأرباح أو المشتريات. |
| مسؤول المشتريات | الموردون والمشتريات والشحن وتوزيعه، عرض الاستلام، والتكلفة وذمم الموردين. يعد مرتجع الشراء ولا يعتمده افتراضياً. |
| مسؤول المخزن | الأصناف والاستلام والدفعات والتحويلات والجرد وتسويات الجرد كمسودات؛ يثبت الجرد ويعتمد الاستلام والتحويل، ولا يعتمد تسوية العجز افتراضياً ولا يرى التكلفة. |
| المحاسب | القيود اليدوية والسندات والتحويلات والمصروفات والرواتب والأصول والتقارير والتدقيق. لا يدير المستخدمين أو النسخ الكاملة أو إغلاق الفترات أو عكس القيود افتراضياً. |

المدير يعدل هذه البداية من صلاحيات الحساب. العرض والإضافة والتعديل والاعتماد ليست صلاحية واحدة.
الحذف لا يمنح افتراضياً للأدوار الأربعة الأخرى؛ يمكن منحه لمسودات وجداول محددة.

## الأذونات الحساسة

- عرض عمليات جميع الموظفين: يعمل داخل الجداول المسموحة؛ لا يفتح كل أقسام البرنامج. المستندات القديمة التي لا تحمل مالكاً تظهر لمن يملك هذا الإذن.
- استخدام جميع الصناديق: يتجاوز قائمة الصناديق المسندة للحساب. القيد اليدوي يتطلب هذا الإذن لأنه يستطيع التأثير في حسابات الترحيل مباشرة.
- عرض التكلفة: يحكم الحقول في النماذج والقوائم والتفاصيل والبحث والمرشحات والطباعة والتصدير والمخزون. ملخص شراء يخفي إجمالياته أيضاً عند حجب التكلفة.
- عرض الأرباح: مطلوب مع عرض التكلفة للدفتر المحاسبي الكامل والتدقيق وميزان المراجعة والدخل؛ هذه السجلات تتيح استنتاج الأرباح والتكلفة.
- تغيير الأسعار: مطلوب لتغيير سعر سطر بيع **محفوظ كمسودة**. المخطط الأصلي لا يتضمن قائمة أسعار بيع مرجعية؛ إدخال السعر الأول ليس تجاوزاً لسعر قائمة، ولا نضيف سياسة خصم أو حد سعر من عندنا.
- اعتماد المرتجعات: مطلوب إلى جانب اعتماد جدول المرتجع.
- اعتماد تسويات وعجز الجرد: مطلوب إلى جانب اعتماد التسوية. إعداد المسودة وتثبيت الجرد لا يمنحان الاعتماد.
- إنشاء قيد يدوي، وعكس قيد يدوي، وإغلاق/إعادة فتح الفترات والسنوات: أذونات مستقلة.
- النسخ الكامل والاستعادة: منفصلان عن تصدير CSV. نسخة SQLite تحتوي **جميع بيانات المتجر وحساباته وتجزئات كلمات المرور**؛ لا يحدها نطاق الموظف أو حجب التكلفة.
- إدارة المستخدمين: المدير فقط يستطيع إنشاء مدير آخر أو تعديل حساب مدير. المفوض بإدارة الموظفين لا يمنح صلاحية لا يملكها.

تقارير الذمم والأموال والمراجعة والدخل تقارير مجمعة للمتجر؛ تتطلب «عرض عمليات الجميع» والأذونات الحساسة المناسبة.
لا نحول رصيد الصندوق المحاسبي إلى «مجموع عمليات الموظف»؛ هذان رقمان مختلفان. تقرير المخزون يعرض الكميات المشتركة ويحجب القيمة عند منع التكلفة.
نطاق البيانات هنا «عمليات الموظف/الجميع» وقائمة الصناديق. لا يضيف هذا الإصدار عزلاً منفصلاً للفروع أو المستودعات.

## الحماية والتدقيق

تفحص طبقة أوامر Python الجلسة والأذونات ونطاق السجلات عند كل قراءة وكتابة؛ واجهة Android تعرض الأزرار المسموحة أيضاً.
يمنع تغيير ملكية السطر بربطه بمستند موظف آخر، واستخدام صندوق غير مسند، وتمرير UserID مزور أو SQL أو تعديل جداول الصلاحيات عبر النماذج العامة.
تنسب CREATE/UPDATE/DELETE وPOST وFREEZE وREVERSE والطباعة والتصدير والنسخ وتعديلات الحسابات إلى UserID والوقت، مع القيم قبل/بعد حيث تنطبق.
ترحيل المصروف الذي ينشئ سداداً تلقائياً يحمل المنفذ نفسه. الحركات القديمة التي ليس لها UserID تبقى كذلك؛ لا نخترع منفذاً تاريخياً.
السجل لا يقبل التعديل والحذف. لا تحفظ كلمات المرور أو رموز الجلسات في السجل. تحتفظ تغييرات الحساب بالدور والاستثناءات والصناديق السابقة والجديدة.
طلبات الطباعة/التصدير في السجل تثبت تجهيز البيانات المصرح بها؛ لا تثبت استلام ورقة من الطابعة أو مشاركة الملف لاحقاً.
يعاد فحص الإذن عند كتابة ملف التصدير أو إرسال مستند الطباعة، بعد عودة منتقي الملفات.

كلمات المرور PBKDF2-SHA256 بعدد 210000 دورة وملح عشوائي، والتحقق بالمقارنة الثابتة. خمس محاولات فاشلة توقف المحاولة لذلك الاسم دقيقة داخل العملية الحالية.
الجلسات رموز عشوائية في الذاكرة؛ لا تحفظ في ملفات الإعدادات أو قاعدة البيانات أو النسخ. إعادة تشغيل العملية تتطلب الدخول.
تجزئات واردة من أدوات أخرى مثل Argon2/scrypt/bcrypt لا يسجل هذا الإصدار الدخول بها؛ ينشئ المالك حساب المدير عند ترقية قاعدة قديمة، ثم يعيد تعيين كلمات حسابات الموظفين من الشاشة عند الحاجة.
هذا ضبط وصول داخل التطبيق؛ ملف SQLite غير مشفر. من يحصل على نسخة الملف أو صلاحيات جذر للجهاز قد يقرأ البيانات خارج التطبيق.

## توافق القاعدة والتحديث

تبقى الجداول الأصلية الـ68 والحقول الـ412 وملف `001_initial.sql` وقيوده كما هي. امتداد الجوال يضيف أربع جداول مساعدة عبر `002_mobile_security.sql`:
`MobileSecurity`، `MobileUserPermission`، `MobileUserCash`، `MobileRecordOwner`.
يظل إصدار SchemaMigration الأصلي 1؛ للامتداد رقم إصدار مستقل. إضافة UserID في تدقيق المحرك اختيارية، ولا تغير الحسابات أو قواعد الترحيل.
الاستيراد يقبل المخطط الأصلي أو المخطط الأصلي مع الامتداد المطابق؛ يرفض حذف/تعديل القيود. تستعاد الحسابات والصلاحيات من الملف، وتنتهي جميع الجلسات.
إعادة قاعدة قديمة دون امتداد تستدعي إعداد المدير من جديد. يحفظ قبل الاستبدال ملف `before-restore.sqlite` متضمناً منفذ الاستعادة.
النسخة القديمة من التطبيق لا تطبق هذه الحماية؛ لا تستخدم إصدار 1.0.0 للوصول إلى نسخة قاعدة محمية.

حزم CI التجريبية تستخدم توقيع Debug قد يختلف بين عمليات البناء. إذا رفض Android تحديث الإصدار السابق بسبب التوقيع، **صدّر قاعدة بياناتك من النسخة القديمة واحفظها خارج التطبيق قبل إزالته**، ثم ثبت الجديد واستوردها. لا تحذف تطبيقاً يحمل بيانات غير محفوظة.
التوزيع المستقر لاحقاً يحتاج مفتاح إصدار ثابتاً يحتفظ به المالك.
