# تطبيق محاسبة المتجر على Android

تطبيق محلي مستقل يستخدم **قاعدة abud.sQllite ومحرك ترحيلها الأصلي نفسه** داخل الهاتف. لا API ولا SQL Server ولا استضافة. أنشئت واجهة Android أصلية بـJava، وضمّن Python 3.12 بواسطة Chaquopy لإبقاء قواعد المحاسبة والتكلفة والمرتجعات الأصلية دون إعادة كتابتها.

## الحالة الحالية

أضيف المصدر ونجح **55 اختبار Python** محلياً بتاريخ 2026-10-21 على Python 3.12 وSQLite 3.53.1. فُحص تركيب مصدر Java بواسطة مترجم JDK 21. **لم ينتج APK ولم يختبر على Android بعد**: منع sandbox الشبكة عند تنزيل Gradle (`java.net.SocketException: Operation not permitted`). لا يكفي فحص تركيب Java لإثبات بناء التطبيق أو توافق مكتباته. ملف workflow المرفق يبني التطبيق ويختبره على محاكي قبل نشر حزمة التنزيل؛ لا توجد نتيجة ناجحة لهذا workflow حتى الآن.

## نطاق الواجهات

- **68 جدولاً و412 حقلاً** وفق PRAGMA في المخطط الأصلي. يعرض [فهرس الحقول](../docs/mobile-fields.md) الحقول القابلة للإدخال والحقول المحسوبة والسجلات المحمية.
- إنشاء متجر جديد بعملة يختارها المستخدم، ودليل الحسابات والصندوق والبنك والسنة الحالية وفتراتها؛ دون منتجات أو أشخاص أو عمليات تجريبية.
- إدخال البيانات الأساسية والمسودات وتعديلها وحذف غير المستخدم منها، مع البحث والصفحات واختيار المراجع من السجلات. يتعامل التطبيق مع مفاتيح الجداول المركبة أيضاً.
- فتح الأسطر المرتبطة من المستند، وحساب إجمالي الفاتورة والمتبقي، واعتماد المستند عبر `Database.post` فقط. تشمل خدمات الاعتماد الـ21 جميع أنواع المستندات المدعومة في المحرك، مع القيد اليدوي وعكسه وتثبيت الجرد بأوامر مستقلة.
- المبيعات النقدية والآجلة والمرتجعات؛ المشتريات والشحن وتخصيصه والاستلام والدفعات والصلاحية؛ التحويل والاستلام الجزئي والجرد والتسويات؛ القبض وتخصيصه والسداد والمقدمات؛ المصروفات واستحقاقها وسدادها؛ الرواتب؛ التوصيل؛ الأصول والإهلاك والاستبعاد.
- ميزان المراجعة وقائمة الدخل وأرصدة الصناديق والبنوك والمخزون الحالي وقيد النقل وذمم الأطراف، مع CSV. دفتر اليومية والحركات والتدقيق متاحة بالكامل بالصفحات دون حد إجمالي لعدد السجلات.
- تصدير SQLite كاملاً واستيراده من منتقي ملفات Android دون صلاحية التخزين العامة، وفحص سلامة الملف ومطابقة مخططه وقيوده وأرصدته قبل الاستبدال. تحفظ نسخة من القاعدة السابقة ويمكن تصديرها من شاشة الصيانة.

## أول تشغيل بعد بناء APK

1. ثبّت `app-debug.apk` على Android 8 أو أحدث، بمعمارية arm64-v8a أو x86_64. اسم الحزمة `com.abud.supermarket.offline` مختلف عن تطبيق الخادم السابق.
2. اختر إنشاء متجر جديد وأدخل الاسم والعملة، أو استورد ملف SQLite منشأً بمحرك المستودع نفسه. رابط GitHub ليس ملف قاعدة؛ أنشئ أو نزّل ملف `.sqlite` ثم اختَره.
3. أضف التصنيفات والمنتجات والموردين والعملاء. لتمويل صندوقك افتح القيد اليدوي، وسجّل مدين حساب الصندوق ودائن رأس المال بالمبلغ نفسه.
4. من فاتورة الشراء احفظ الرأس، ثم افتح «أصناف المشتريات» وأضف الأسطر. ارجع إلى الفاتورة واعتمدها لتثبيت الاستحقاق.
5. أدخل الشحن وتوزيعه إن وجد واعتمده **قبل أول استلام**. أنشئ استلاماً وأسطره، ومن سطر الاستلام أنشئ دفعاته بكمياتها ومنتجها وصلاحيتها. اعتماد الاستلام هو الذي يدخل المخزون.
6. أنشئ فاتورة بيع وأسطرها ثم اعتمدها. البيع الآجل يحتاج عميلاً؛ النقدي يحتاج حساباً مالياً. السداد للمورد والقبض من العميل مستندان مستقلان، وتخصيصاتهما تضاف قبل اعتمادهما.
7. صدّر نسخة احتياطية خارج الهاتف من شاشة الحفظ والاستيراد. إزالة التطبيق أو فقد الهاتف قد يفقد القاعدة المحلية ما لم تحتفظ بنسخة خارجية.

الأسطر تحفظ كمسودات مستقلة حتى اعتماد الرأس. الحقول المحسوبة مثل صافي الراتب، كمية الجرد المسجلة، فرق الجرد ومبلغ الإهلاك يحسبها التطبيق. الحالة POSTED لا تدخل من النموذج؛ السنة والفترة المالية لهما اختيار OPEN/CLOSED.

## البناء والتحقق

المتطلبات على جهاز البناء: JDK 17 أو 21، Python 3.12، Android SDK Platform 35 وأدوات البناء، والإنترنت للتنزيل الأول. الهاتف بعد التثبيت لا يحتاج هذه الأدوات أو اتصالاً بالإنترنت.

```bash
python -m unittest discover -s tests -v
cd android
./gradlew assembleDebug
```

على Windows استخدم `gradlew.bat assembleDebug`. يمكن فتح مجلد `android` في Android Studio وتعيين SDK. ملف التثبيت بعد نجاح البناء في `android/app/build/outputs/apk/debug/app-debug.apk`.

على GitHub شغّل workflow **Standalone SQLite Android** من Actions بعد وجوده في المستودع. يبني APK ثم يشغله في وضع الطيران على محاكي Android 15، وينشئ متجراً وبيانات ويتحقق من بقائها بعد إيقاف العملية وإعادة فتحها. عند نجاحه تظهر حزمة `supermarket-mobile-sqlite`. الحزمة تجريبية موقعة بمفتاح Debug؛ التوزيع الرسمي يحتاج مفتاح إصدار محفوظاً لدى المالك.

## حدود يجب معرفتها

- هذه الواجهة مخصصة لمالك هاتف واحد. جداول المستخدمين والأدوار والصلاحيات موجودة وقابلة للإدارة، وكلمات المرور الجديدة تحفظ PBKDF2 وتُحجب في العرض والتدقيق، **لكن تسجيل الدخول وفرض صلاحيات الموظفين لم ينفذا بعد**. لا تقدم هذه النسخة كحل صلاحيات متعدد المستخدمين.
- الاستيراد يطابق إصدار المخطط 1 وقيوده كاملة. ملف SQLite مختلف، أو ملف حُذفت منه triggers، يرفض دون مسح القاعدة الحالية. حد الاستيراد 100 MiB.
- تقريرا ميزان المراجعة والدخل والحسابات المالية يحترمان تواريخ القيود. تقرير المخزون وقيد النقل حاليان. تقرير ذمم الأطراف يعرض صافي الفواتير حتى تاريخ النهاية بعد المرتجعات الحالية؛ ليس تقرير ذمم تاريخياً مجمداً. إذا ارتبط حسابان ماليان بنفس حساب الترحيل، يظهر لهما دفتر رصيد مشترك.
- جميع السياسات والحدود في [مراجعة التصميم](../docs/design-review.md) و[دليل المحرك](../database/README.md) باقية: عملة واحدة، لا ضرائب أو خصومات أو تعدد عملات مفترضة، لا تسوية لاحقة للمقدمات ولا شحن متأخر بعد الاستلام. لا يفرض المصدر منع رصيد مالي دائن دون سياسة إضافية. لا توجد مزامنة تلقائية بين الهواتف أو الطباعة الحرارية أو مسح الكاميرا.
- هذه شاشة نماذج عربية شاملة للمخطط، وليست واجهة كاشير سريعة ذات سلة مختصرة. اعتماد الحركات المحاسبية محكوم بالمحرك والقيود؛ تبقى تجربة APK الفعلية مطلوبة قبل البيانات الحقيقية.
